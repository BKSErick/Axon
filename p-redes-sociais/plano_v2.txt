2.3 Requisitos nas contas dos clientes

PRÉ-REQUISITO POR CLIENTE
Antes de conectar qualquer cliente ao MetaReports, verificar TODOS os itens abaixo. Uma conta que não atenda a esses requisitos simplesmente não funciona com a Meta Graph API, independente de qualquer configuração do sistema.

FB
Página do Facebook (não perfil pessoal) Verificar por cliente
A publicação via API só funciona em Facebook Pages. O cliente deve ser administrador da página, não apenas editor.

IG
Conta Instagram Business ou Creator OBRIGATÓRIO
Desde dez/2024 a Meta descontinuou a Basic Display API. Contas pessoais não funcionam mais com a Graph API. Precisa ser Business ou Creator.

↔
Instagram vinculado à Página do Facebook OBRIGATÓRIO
Mesmo com conta Business, se o IG não estiver vinculado à Page do FB, a publicação falha. Configurar em: Instagram > Configurações > Conta > Página vinculada.

PPA
Page Publishing Authorization Verificar cada página
Algumas páginas exigem PPA — autorização extra da Meta para publicação via API. Verificar em: Configurações da Página > Autorização de Publicação de Conteúdo.

3. Modelo de Agendamento por Plataforma
Facebook e Instagram têm comportamentos diferentes na API. O dev precisa implementar os dois modelos.

3.1 Facebook — Agendamento nativo via API

COMO FUNCIONA
O Facebook suporta agendamento diretamente na chamada de publicação. Basta passar published: false e scheduled_publish_time (Unix timestamp UTC) no POST /{page-id}/feed. A Meta publica automaticamente no horário. O tempo mínimo é 10 minutos à frente e máximo 6 meses.

Exemplo de payload para post agendado no Facebook:

POST  /{page-id}/feed
{ &quot;message&quot;: &quot;Texto do post...&quot;, &quot;published&quot;: false, &quot;scheduled_publish_time&quot;: 1741996800 }

3.2 Instagram — Agendamento via BullMQ
O Instagram NÃO tem campo scheduled_publish_time. O fluxo é mais longo e controlado pelo sistema:

Criar container de mídia — POST /{ig-user-id}/media com image_url ou video_url, caption e demais campos
Aguardar status FINISHED — GET /{container-id}?fields=status_code (polling a cada 5s)
Job BullMQ dispara no horário agendado — o worker executa a publicação
Publicar — POST /{ig-user-id}/media_publish com creation_id={container-id}
Registrar resultado — salvar media_id ou erro no banco de dados

IMPORTANTE
O container de mídia criado no passo 1 expira em 24 horas. Crie o container apenas momentos antes da publicação (até 1 hora antes), não no momento que o post é agendado. O job BullMQ deve criar o container e publicar em sequência.

Toda mídia deve estar hospedada em URL pública (S3 ou Cloudflare R2) no momento da publicação. A Meta faz download da imagem/vídeo diretamente via URL. Não funciona com localhost, URLs com autenticação ou links temporários com expiração curta.

4.3 Estrutura da chamada — exemplo de código
const res = await fetch(
  &quot;https://generativelanguage.googleapis.com/v1beta/models/
   gemini-2.0-flash:generateContent?key=${GEMINI_API_KEY}&quot;,
  { method: &quot;POST&quot;,
    body: JSON.stringify({
      contents: [{ parts: [{ text: prompt }] }]
    }) })

A resposta vem em: res.candidates[0].content.parts[0].text

4.4 Estrutura do prompt para posts
O prompt enviado ao Gemini deve sempre incluir contexto completo para gerar textos coerentes:

Identidade do cliente: nome, nicho, público-alvo, tom de voz cadastrado
Plataforma e tipo de post: Feed IG, Carrossel FB, Stories, etc.
Tom de voz da solicitação: profissional, descontraído, urgente, etc.
Briefing preenchido pelo usuário
Últimos 3–5 posts de melhor desempenho do cliente (contexto histórico)
Instrução de formato: quantidade de slides se carrossel, duração se Reels, etc.
Idioma: &quot;Responda apenas em português brasileiro natural&quot;

5.1 Gestão de Page Tokens — ponto crítico

TOKENS EXPIRAM
Page Tokens de longa duração duram até 60 dias. O sistema deve: (1) armazenar tokens criptografados com AES-256 no banco, (2) rodar cron job diário verificando a validade, (3) enviar alerta por e-mail/notificação no sistema 7 dias antes do vencimento, (4) oferecer fluxo de re-autenticação OAuth na interface do MetaReports. Tokens expirados resultam em erro #190 na Meta API.

9.2 Boas práticas obrigatórias
Todos os Page Tokens armazenados com AES-256 no banco — nunca em plain text
Variáveis sensíveis (API keys, secrets) exclusivamente em variáveis de ambiente
HTTPS obrigatório em todos os endpoints de callback OAuth
Logs sem dados sensíveis — nunca logar tokens, senhas ou dados de clientes
Validar tamanho e formato de mídia no frontend antes de fazer upload para S3/R2
Implementar retry com backoff exponencial nos jobs BullMQ (1min → 5min → 15min)
